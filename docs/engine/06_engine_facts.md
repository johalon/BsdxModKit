# 06 エンジン仕様の早見 — DiveX（NeXAS）と BFE でわかっていること

変換・調整のたびに引く「事実」だけを並べた早見表。経緯は書かない（経緯は各 notes）。数値・アドレス・スロット番号は原文（notes/・tools/）で確認して写した。
パスの表記は `<PROJECT>` = ワークスペースのルート（制作記録 冒頭）。アドレスは VA（ImageBase 0x400000）。

## 0. 読み方

### 確度の記号
| 記号 | 意味 |
|---|---|
| 【exe】 | exe の逆アセンブル、またはバニラ全件データの照合で確認（資料の「確定」「確認済」のうち実機に依らないもの） |
| 【実機】 | 作者の実機確認（制作記録 の OK）または動画の測定で確認 |
| 【推定】 | 名前・並び・統計・状況証拠からの推定（資料の「推定」「有力」「推測」） |
| 【未確認】 | 資料に「未確認」と書かれているもの |

資料間で食い違うときは日付の新しい方を採り、「旧: … → 現: …」と書いた。食い違いと古い記述の一覧は §12。

### 略号
* DiveX = BALDR SKY DiveX（BaldrSky.exe v1.07）。BFE = BALDR FORCE EXE（BaldrForce.exe）。
* ターン = NeXAS_DX の "phase"（waz の中の段）。BFE の「フェーズ」と 1:1 で変換する（調査記録 09 §3）。
* F = DiveX のフレーム（60fps）。tick = BFE の 1 単位（30fps）。**1 tick = 2F**（BFE のフレーム間隔表 0x4e0634 = {66,50,33,16}ms、既定 index 2。調査記録 09 §2）。
* 3b = 原作再現版（faithful）。modified = 改善版。waz110 = variantB_waz110 版（WazaGroup の空き [110] を使わない）。

### 1.4 pac と読み込み（Update3.pac に入れる）【exe】docs/formats/02_pac_and_loading.md
* 新形式。末尾にインデックス（Huffman → 全バイト NOT）。エントリは cp932 名 + offset + 展開サイズ + 圧縮サイズ。**type 4 の判定は拡張子**: `ogg / wav / png / fnt / mpg / mpeg / avi` は無圧縮、**それ以外は必ず zlib（level 6）**（自作 pac で守る。`tools/nexaspac.py` は実装済み）。CRC・ハッシュ検査は無い。
* マウント優先度（高い順）: **Update7 > … > Update3 > Update2 > Update > MascotVoice > Voice > Stand > Face > Thumbnail > System > Script > Bgm > Visual > Movie > Se > Config > PlugIn01..08 > Bmp > Dat**。キーはファイル名のみ（pac 名・フォルダなし、小文字化）。先にマウントした pac が勝つ。Update3〜7 は無くても黙って飛ばされる。**Update3.pac を作ってゲームフォルダに置けば exe 無改造で上書きできる**。
* ルーズファイルは使えない（Movie のみ）。ファイル名は cp932 で 63 バイト以内。

## 2. waz の構造とスロット

### 2.1 構造【exe】docs/formats/05_waz_field_dictionary.md §1
```
waz = skillList[]      // index = 技番号。mek の武装.wazSequence / CEventWazaSelect.wazSequenceNo が指す。null = 空き
skill = { skillNameJapanese, skillNameEnglish, phasesInfo[] (= ターン), skillSuffixList[] }
ターン = skillUnitCollection[]   // 存在するスロットだけ並ぶ
スロットの束 = { unitQuantity, skillInfoObjectList[], skillInfoUnknownList[] }
イベント = { startFrame, endFrame, …型固有… }  // ターン内のタイムライン。start〜end の間だけ有効
```
* **`unitQuantity` は「個数」ではなく「スロット番号（0–71）」**（名前が紛らわしい）。JSON パス: `skillList[s].phasesInfo[turn].skillUnitCollection[unitQuantity==N].skillInfoObjectList[]`（`tools/waz_fields.json` の `slots[].json_path`）。
* ターンの移動（次のターン・指定ターン・技の終了・別の技）はスロット 71 の変更処理（ターンジャンプ）だけで行う。ループもこれで作る。
* `skillSuffixList` は (ターン番号, 0) の並び。エディタのツリー表示用と見られる【推定、編集対象外】。`skillInfoUnknownList` は 99% が (-1, 1, -2)【不明、触らない】。

### 2.2 値イベント（CEventVal / CEventValRandom）【exe】docs/formats/05_waz_field_dictionary.md §1.1
| JSON | CEventVal | CEventValRandom |
|---|---|---|
| int1 | 開始値タイプ（0 直値／1 前の値±） | 開始値タイプ |
| int2 | 開始値 | 開始値 |
| int3 | 終了値タイプ（0 直値／1 前±／2 開始値±） | 開始値の乱数幅 ± |
| int4 | **終了値（主値）** | 終了値タイプ |
| int5 | — | **終了値（主値）** |
| int6 | — | 終了値の乱数幅 ± |
* start→end の間で補間する。開始値は区間が 2F 以上のときだけ使われる。**主値は Val = int4、ValRandom = int5**。

### 2.3 Term（条件・指定子）docs/formats/05_waz_field_dictionary.md §1.2
* `bsdxInfoCollection` は Term.grp（30 グループ）の語彙の式。`int1` = グループ番号【exe】: 位置 = 20 POS、無効条件 = 4、方向 = 18 ANGLE、速度タイプ等 = 23 PARAM、**攻撃力 = 21**、変更処理の条件 = 0、飛び先 = 16 JUMP。
* `typeList` = 項目番号の列【推定・高確度】。`paramList` = 項目文字列の `$v1`、`$v2` に入る数値【exe】（0x63bf50）。`intList3/4` = 対象オブジェクトの選択値【不明】。

### 3.2 ダメージ計算 0x63ba40【exe】docs/formats/05_waz_field_dictionary.md §3.1、調査記録 18 §N
```
base = p                           (typeList[0]==0: 直値)  / 自HP×p/100 (==1) / 敵HP×p/100 (==2)
base ×= 150/100   ← 攻撃元オブジェクトの持ち主 [src+0x14c4] が ①自機（vf 0x158、出撃情報フラグ bit2。0x629398）かつ ②MekaGroup 番号（+0x18a4）≠ 0
d = base × (100 − 累積補正) / 100  （補正率。0x61ec7c: 100 −(+0x10c + +0x104 + 技のみ(相手ごと) + +0xa4)）
d = max(d, minDamage)              ← 最低値には ×1.5 が掛からない（0x63bb1a / 0x63bb51）
if chargeDamageRate >= 0: d = d × (溜め量% + chargeDamageRate) / 100
```
* ×1.5 の条件の「自機」判定（vf 0x158）は【推定・有力】（0x629398 でプレイヤー番号を入れる所で bit2 を立てる）。MekaGroup ≠ 0 は**甲（0）だけが ×1.0**。弾にも効く。透（MekaGroup 10）の自機は常に ×1.5【exe・実機: 移植版 DD 1 発目 262 = 175×1.5】。
* **累積補正がマイナスなら 100% を超えて威力が上がる（上限なし）**【実機】作者 11/10。
* **ヒットごとの補正の半分化**: 攻撃側が自機で MekaGroup = 1（マサ）または ≥ 27（ザコ）のとき mid を半分にして加算（0x6061b9）。透（10）には効かない【exe】。
* 威力の換算は **BFE ÷4 で確定**（制作記録「変換の方針」）。表示では透は甲換算の 1.5 倍になる（÷6 に変える案は大きな変更なので保留）。

### 5.2 BFE のダメージ式との差【exe】調査記録 07 §2.4、調査記録 B4 §2
```
BFE: dmg = max(威力 × P/10 − combo×P/10, 最低威力)；combo += ｺﾝﾎﾞ補正（攻撃側 CPU なら ×3/4）

DiveX: dmg = max(⌊表示威力 × (100 − 累積)/100⌋, 最低値)        ← 引き算 vs 掛け算
```
* 原作は「引き算」で威力の大きい段は減りにくい。DiveX は「掛け算」で、次の段の威力に応じて補正を変える欄が Hit に無い → **長いコンボの最後の段が原作より小さい**のは DiveX の式の構造上の制約（近似として残る）【exe】調査記録 18 §N。

### 5.3 FC とイニシャライザ（有志 wiki）docs/game_spec/37_game_spec_combo.md【wiki。作者: 信頼性は非常に高い】
* イニシャライザでコンボをもう 1 ループできる。**イニより前に、イニ以外の FC を使うと累積補正は 0 にリセット。イニより後に、イニ以外の FC を使うと 50 にリセット**。FC がヒットすると FC 自身の補正が普通の武装と同じく足される。**イニの補正は 25、イニは補正をリセットしない**。【未確認】二周目の最初の技に初段補正がもう一度かかるか。
* コンボの長さ（作者 11/10）: 武装枠は通常 12 + FC/イニ 2。通常 12 のうち 1 つは防御技で確定 → 攻撃技は 11。一周目は 8 技ほど、イニ後は全技が再び使えるので 11 技。
* **コンボ中に同じ技は振れない**（ゲームの仕様、制作記録）。

### 5.4 熱量（ヒート）【exe】調査記録 22
* **DiveX**: 1 ゲージ = `[mech+0x1914] = 0x1f40 = 8000`（0x617bb4）= **熱 80**。熱の上限は 3 ゲージ（0x61d84d）。加算後に（1 ゲージ − 熱）/100 ≤ 0 でオーバーヒート（+0x18e8 = 1、0x61d875 / 0x6172e0）。オーバーヒート中は HC フラグ無しの武装が使えない（0x61a617、有力）、熱が 0 まで下がると解除（0x61d8bf）。技開始 0x61cd1e〜: 消費 ×100 を `[mech+0x191c]` に入れ、**3F 後（+0x1918）に 0x61d830 で熱 `[mech+0x1910]` に加算**。
* 武装の熱の決まり方: MekaGroup = 0（甲）: CPU なら heatMin、自機なら甲の武装状態（成長あり）。**MekaGroup ≠ 0 の自機は 0x65bdb0: 通常武装（カテゴリ 0）= heatMin ≠ 0 なら heatMin、0 なら HC フラグ付きは heatMax・それ以外は heatMax/2（切り捨て）。FC = heatMax。イニシャライザ = 0。成長（使い込みで下がる）は無い**。自機でなければ heatMax。
* **BFE**: ヒート最大 130（0x41b560 既定、状態 +0x20/+0x22）。消費 = `base = OH × ヒート率/100`（打撃/射撃、100/100）→ `cost = max(base − R, base/3)`（R = 使い込み軽減。プレイヤー、`0x41ad50`）→ `min(cost, 130)`。**130 以上で 130 に張り付きオーバーヒート**（0x41af2f）。R の成長は OH/3 を下回らない所で止まる（0x44dca6〜0x44dcc1）、R 上限 130、超技は R = 0。→ **完全成長時の消費 = OH//3**。
* **換算（HEAT 規則）**: `heatMin = max(1, round(OH//3 × 80/130))`（最小 1 = 0 にすると 0x65bdb0 が heatMax/2 にフォールバックするため）、`heatMax = max(2, round(OH × 80/130))`（CPU で使うときだけ）、FC は甲テンプレの heatMax 80 のまま・heatMin 0（超技 130 = 満タン・成長なしと一致）、イニ 0。武装名での分岐なし。
* 甲のバニラ値も heatMin ≒ heatMax/3 で、成長倍率は BFE と同じ約 1/3。

### 5.7 ヒットロック【exe】調査記録 36

## 6. キャンセルと技後の慣性

### 6.1 DiveX のヒット時・射出時キャンセル【exe】調査記録 20 §1

  | 0 / 1 | [+0x1900] = 値（不可 / 可） |
  | 2 | 状態が 2（ヒット済み）なら 1 に昇格（Hit +0x64 = 2 と組で「当たってから可」） |
  | **3** | **[+0x1904] = 1。その区間だけ DiveX 独自の「キャンセル操作」（EX キャンセル、0x617130）が可。ゲージ [+0x1928] を使う**。武装キャンセルとは別の仕組み |

### 6.2 BFE の原作仕様【exe】調査記録 20 §2、制作記録
* **近接はヒットで、射撃は弾の射出でキャンセル可**。次の技を入力しなければキャンセルされない。多段技は打撃部が 1 発でも当たれば可。
* 機体構造 [obj+0x38] の **+0x3e** がキャンセル可フラグ（判定 0x418181 / 0x418630、CPU 0x453003 / 0x4537b0）。
  * 命中（0x441510、被弾側がメカのときだけ 0x4416cc）: 攻撃したオブジェクトの武装スロット +0x284 が持ち主機体の今の武装スロットと同じで（0x44185d-0x441863）、**そのオブジェクトの技の「技タイプ」（ヘッダ +0x29）が 0 = 打撃**なら持ち主の +0x3e = 1（0x44186b-0x441878）。多段でも 1 発目で立つ。
  * 発射（0x44a7dc-0x44a81b）: 撃ったのがメカで技タイプ 1 = 射撃なら +0x3e = 1。
  * フェーズ開始（0x443d20-0x443d41、メカだけ）: flags bit6「空ｷｬﾝｾﾙ」→ 1、それ以外で bit7「ｷｬﾝｾﾙﾌﾗｸﾞ初期化」→ 0。技の終了 0x43f0d0 で 1。技の開始 0x43f1d0 は触らない。

### 6.3 変換規則 HITCANCEL（R）【exe。実機確認は個別に OK 済みのものあり】
1. 機体の技の Hit（slot 41）: BFE の技タイプ = 打撃 → `selfStunFrame` = 1、射撃 → 0。対弾（slot 42）は 0。
2. 弾の Hit（対メカ）: その Tama 自身の技タイプが打撃、かつ打撃技から（弾経由も含め）撃たれる Tama → 1、他は 0。ライン（レーザー・ワイヤー）の Hit も同判定。
3. slot 47（機体の技のみ、1F の (0→v) イベント = 甲の形）: フェーズ flags bit6 → F0 に 1、bit7 → F0 に 0（ターン 0 は DiveX が開始時に 0 にするので出さない）、射撃フェーズで弾を撃つ → その発射フレームに 1。テンプレ由来は値 3 の窓だけ残し 0/1/2 は落とす。

### 6.4 技後の慣性（slot 33 と技の終わり）【exe】調査記録 19
* **slot 33（0x618150）は技が自然に終わったときには呼ばれない**。呼び出し元は 2 か所だけ: 0x61ca8a（技の開始 0x61c980 で前の技がまだ動いている = 技→技のキャンセル）、0x61c893（キャンセル操作 0x61c790。入力 0x873df8 bit2 と回数 [+0x1928] を見る 0x617130 を通る）。
* 作用: 横速度を [long1, long2] に制限して滑りへ移し、vz を [int1<<10, int2<<10]、重力率 +0x177c を [int3, int4] に制限（重力の下限 50）。既定値 0x607590 = (0, 0x1000, 0, 6, 0, 100)。
* **技の自然終了（ターンジャンプ→終了）**: 機体が状態に入り直すときの enter が 0x6299d0 を呼び、**重力 +0x20 を「(g + 0x200) & ~0x3ff < 0xc800 なら 0xc800」= 50 に切り上げるだけ**。vz はそのまま残る。→ 技が終わった後は vz − a、vz − 2a、…（a = 重力/200 px/F²）。技の終了時に重力を 50 より大きくすれば上昇の頂点を調整できる（バニラ実例 27 件: アカオ 空中ファントム 100、村正 臥竜 200 など）。

* BFE 側の技の外は **v += −128 /tick、高さ += sign(v)·(v>>8)²（±48 で頭打ち）**（§10.3）。技後の上昇は「頂点の高さ」を原作に一致させる（着地時間は不要）。POSTAPEX 規則（作者 10/29）。

## 7. 被弾側の物理（のけぞり・ダウン・打ち上げ）

### 7.1 のけぞり（Hit のサブ 17–20 = CEventNokezori）【exe】docs/formats/05_waz_field_dictionary.md §4.2、docs/game_spec/41_terms_ux.md、調査記録 31、調査記録 43
* **欄の選び**: 17 地上→地上 / 18 空中 / 19 空中→地上 / 20 ダウン中の相手。`int1` 処理タイプ: 0 = この欄の値、1–4 = 地上・空中・空中→地上・ダウンの欄と同じ、5 = のけぞらない。

* **ﾋｯﾄﾊﾞｯｸ = 0 だと ダウン時間 int7 を記録せず（0x619230 → 0x619246）、この経路の縦の吹き飛びもしない（0x61914a）**。打ち上げ技は着地まで硬直が続く長さにしないとダウンしない（バニラ DDミサイル：甲Lv3 は 100/200、滞空 80F）。NOKEDOWN 規則 = int3/int4 を `max(テンプレ, 2 × DiveX の滞空 80×規模/重力)` に（BFE の吹き飛び = 蓄積 100 以上かつ規模 > 0）。

### 7.2 打ち上げの物理と重力【exe・実機】SIGN_DECISION 10/30 追記、調査記録 18 §M2
* 被弾側の重力: 0x616795 で **0xc800（= 50×1024）× 吹き飛び重力 %** を 0x5f4be0 が **/200** で引く → **0.25·%/100 px/F²**。上向きの速さ = 規模/10 px/F。→ 頂点 **H = 2·規模²/%**、滞空 **T = 80·規模/%**。

## 8. 弾・エフェクト・ライン

### 8.1 共通 waz と生成
* 弾・エフェクトは**共通 waz**（WazaGroup: 0 Effect、1–5 Tama01–05、6 Laser、7 Bomb）の技。機体の技は **slot 48（CEventEffect）の生成イベント**で出す。威力・ヒット数は**生成先の技の slot 41**にある。参照数（全 waz）: Effect 3297、Laser 593、Bomb 318、Tama02 294、Tama01 287、Tama05 236、Tama04 183、Tama03 95。
* `CEventWazaSelect{wazFileNo, wazSequenceNo}` = 生成先。透は **Tama04 の末尾（109→194）に BFE の弾 85 種、Tama02 の末尾（98→113）に BFE のヒットエフェクト 15 種、Laser の末尾（185→209）にレーザー／ワイヤー 24 技**を足している（調査記録 09 §0）。共通 waz はバニラのバイト列が先頭にそのまま残る（末尾追加のみ）。
* 生成イベントのヘッダ（slot 48 の int1/int2/int3）【exe】調査記録 24 §S2、調査記録 18 §S3・§L:
  | 項目 | 意味 |
  |---|---|
  | int1 エフェクトタイプ1 | **0 = 見た目だけ（オブジェクト型 3、0x645254。当たらない）**、≠0 = 弾（型 1）。弾のファイル宛ては int1 = 1 がほぼ全部 |
  | int2 エフェクトタイプ2 | **1 = ライン親（CLaser）を作る**（0x64524c → 0x645f87 → ctor 0x615560）。Laser 以外宛てでは 0 にする（SPAWNTYPE） |
  | int3 フラグ | **bit1（値 2）が付くとライン親は敵・弾を貫通する**（ctor 0x615651: `CLaser+0x1860 = フラグ & 2`） |
  | sub[3] | エフェクト番号（WazaSelect）。sub[4] 同時発射数、[5] 最大発射数、[6] 発射間隔、[7] 発射位置、[8–11] 位置補正、[13–14] 発射方向補正、[15] 発射ＳＥ、[16–24] スプライト、[25–27] 位置（25 = オブジェクト位置指定）、[28–35] ベクトル（28 方向、31 速度、33 重力）、[36] 汎用変数、[37] 溜め攻撃力、[40] 耐久力 |
* 弾の向き: 移動する弾の生成には sub 28「ﾍﾞｸﾄﾙ：方向 = 角度指定→スプライト方向(0,0)」が必要（バニラの慣例。無いとエンジン既定の向きになる）【有力】調査記録 16 §S-0。
* スプライト拡大: 生成された物の基本の拡大 X/Y = 生成イベントの値（0x611966 / 0x61196f → +0x16a8/+0x16ac）。子自身の slot 1/2/3 が上書き（§2.4）。

### 8.2 ライン（レーザー・ワイヤー）【exe】調査記録 18 §L、調査記録 24 §L
* 構成: ライン親（CLaser）→ ライン子（線分）→ 先端。次の子の位置 = 前の子の連結点（spm の hitFlag bit5 の矩形）を拡大して読んだもの（0x664b70 → 0x607e60）。**ライン親の毎フレーム処理 0x614ff0**:
  * +0x1860 = 0（int3 bit1 なし = **敵で止まる**）: 攻撃：弾（slot 42、0x648b10）か攻撃：メカ（slot 41、0x648330 / 0x649070）に最初に当たった子の番号を「切る位置」とし、**その子から最後尾までを消す**。ライン親は次のフレームから子を足し直す → 線は敵の位置で止まり、敵が動けば伸び縮みする。
  * +0x1860 ≠ 0（bit1 あり）: 判定だけして子は消さない = **貫通**。
* 対象ごとのヒット記録が「ヒット数」に達した相手は判定から外れる（0x64858a）→ **ヒット数がある敵で止まるラインは、使い切ると以後貫通する**（ラインレーザー Lv3 の照射終わり 16F だけ貫通。原作の線分は 1 ヒットで消えて補充されるので上限なし）。規則 PIERCE: ライン親のヒット数 = -1（無制限）＋間隔（敵で止まる光線のバニラはすべて -1 ＋間隔）。
* バニラの使い分け（ライン親を作る生成 413 件）: bit1 あり（貫通）41 件 = 甲レーザー Lv1–3・パルスレーザー・火炎放射・スィングワイヤー ほか。bit1 なし（敵で止まる）372 件 = 甲レーザービット・アキ「ラインレーザー」・クォウトワイヤー・モーニングスター ほか。
* BFE: 線分が go_hit_mech = 99 ならメカに当たると消え、根元が毎 tick 補充（0x4498b0）→ 敵で止まる。持たない線分（ワイヤー 63/68/75、うねうね 105）は貫通。原作ワイヤーは弾に当たると消えるが、DiveX は弾とメカを同じ bit で扱うので両立不可（メカ貫通を優先）。
* **PIERCE の現行方針（11/02 作者）**: ライン系は「敵で止まる」を優先。ただし**クォウトワイヤー・モーニングスターは敵・弾とも貫通**（制作記録）。
* ライン子のヒット間隔: 回数無制限・全弾更新のライン当たりは **2×(HIT規模+1) F**（LINEIV。スウィングワイヤー 1F→6F ほか）。

### 8.3 追従と位置ロック（slot 11）
* **追従弾（slot 11「前指定を維持」）**: §2.4 slot 11。「弾発射位置ﾛｯｸ」（BFE 0x4437a8: 発射位置をイベント開始時に 1 回だけ計算して固定）付きの追従弾は、**撃った場所に残す**のが原作（透に付いて行かない）。DiveX の生成 sub 25「オブジェクト位置指定 自分」は毎フレーム読み直す（0x60bd70 → 基準点 +0x16dc、0x610e70）ので、発射点が動くたびに弾が飛ぶ（調査記録 57 §3）。
* 現行（11/15 夜）: **エネルギーフィールド・ギガンテックフィールドは甲と同じ組み方**（T0 だけ slot 11 追従、後段は slot 11 なし・速度 0）、撃った側のアニメが発射ターン内で変わるフレームで追従を止める（FOLLOWCUT、ワークアラウンド）。【実機 OK】調査記録 60 §7–8。
* 位置補正（BFE 発射の位置補正 → 生成 sub 8/9/10）は POSCORR で写す。

### 8.4 弾の速度・縦・数
* **速度**: 弾は BSPEED（slot 25 = 50% ＋ slot 18 に生の値）で v/2 px/F。残る近似: BFE は加減速中も整数 px/tick、DiveX は線形補間【実機】調査記録 18 §S1。**機体の速度は 1:1（目安合わせ）で、奇数速度の丸め・機体 slot 15 の角度符号は未対応**（HANDOFF §3 未解決 1）。
* **縦**: 弾の BFE 縦も §10.3 の式。BFALL: x開始 ≤ 0・フラグ 2（最低高さを直値）・最低高さ 0・go_land あり・実効重力 < 0 の弾は slot 19 で落とす（ガトリング、マインスイーパ）。
* **発射間隔（FIREIV）**: BFE は (間隔+1) tick ごと = **2×(間隔+1) F**（火炎放射器の 136F で動画確定）。BFE 0x44a1c0: タイマー（+0x290）を減らす前の値が 0 以下なら撃つ、撃ったら T（0x4a7db0: 累積 +0x2a8 += 増分、T = 累積>>8、最終で頭打ち）。撃ち終わるまで型（anim_type 4）はアニメの周期の整数倍で終わる（0x4433c5）。
* **スプライト拡大タイプ 0（ZOOMTYPE0）**: BFE はイベント開始で拡大のタイプのバイトを読まず初期値を入れる（0x443727 → 0x440dd0）→ タイプ 0 の拡大も原作で効く。DiveX は弾（と拡大する技）の**全スプライトイベントに slot 1** を出さないと前の拡大が残る。
* **ループ（LOOPPOS）**: BFE 0x443491〜0x4434d3: 開始・終了は**技順の位置**（フェーズ番号ではない）、回数 = 通過の総数、カウンタはループごとに別で抜けるとき 0。DiveX の汎用変数は 1 つなので、しきい値 = 技順で前のループの回数の合計 + 回数 − 1。ループがターン 0 に戻る場合はターン 0 F0 の初期化を入れない（エンジンが開始時に 0 にする）。
* 弾の色変化（感電の色）・同じ技の弾どうしの HIT規模共有は DiveX に相当を作っていない（HANDOFF §3）。**NODMG（BFE ヒットフラグ bit5「ﾀﾞﾒｰｼﾞ処理をしない」）の感電は slot 41 を作らない（威力 0 の判定に戻したが、コンボ表示・タイマーへの影響は未確認）**。

### 10.3 上下方向（g_eff）【exe・実機】work/tooru_port/SIGN_DECISION_20261029.md

### 10.5 BFE の原作ゲーム仕様（制作記録 大目的、作者）
* **近接は技がヒットしたら、射撃は弾が射出されたら、次の技でキャンセル可能**（§6.2）。近接はこれでコンボを組むのがメインコンテンツ。原作は BU（ブーストアッパー）始動一択だった（作者 11/10）。
