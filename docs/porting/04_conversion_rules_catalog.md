# 04 変換規則カタログ（原作再現版）

BFE（BALDR FORCE EXE）の透（TOORU）の技を BALDR SKY DiveX（BSDX）の waz へ変換する規則のうち、**名前（大文字タグ）が付いているもの**を、一覧にしたもの。

* 対象は原作再現版（3b / faithful、`variantB_waz110` を含む）。**改善版（modified）だけの調整**（`tools/modified_tweaks.py` の項目、別担当）は含めない。ただし「原作版から改善版へ移した規則」は §10 に書く。
* タグ名の正は `notes/` と `work/tooru_port/制作記録`。コード中のタグは `tools/provenance.py` の `KIND_CAT`（Report の種別）と突き合わせた。Python の定数名（`DASH_SPEED` など）は規則タグではないので省いた。
* **大原則**（HANDOFF §2、調査記録 15 §1）: 武装名で分岐して値を差し込まない。直すときは規則そのものを直し、同じ形の全武装に効かせる。根拠は (a) 原作 exe（BaldrForce.exe）の処理、(b) バニラ BSDX 機体の実例、の両方。
* 分類記号（`KIND_CAT`、調査記録 15 §2）: R = exe かバニラで裏付けた変換 / E = 係数や意味が推定 / V = バニラの書式の流用 / T = 甲テンプレ値のまま / M = 手入力。**ワークアラウンドは E か、表中で「WA」と書いたもの**（§9）。
* 実装場所は 2026-11-16 朝の git HEAD の grep による。行番号は目安（`L1234`）で、編集でずれる。`waz` = `tools/bfe2bsdx_waz.py`、`tama` = `tools/bfe2bsdx_tama.py`、`line` = `tools/bfe2bsdx_line.py`、`basic` = `tools/bfe2bsdx_basic.py`、`build` = `mods/phase3b_tooru/build_phase3b.py`。
* アドレスの書き方: BFE = BaldrForce.exe（原作）、BSX = BaldrSky.exe（DiveX、`BaldrSky_slots_EXPERIMENTAL.exe` 系）。「slot N」は waz のイベント種別番号（`docs/formats/05_waz_field_dictionary.md`）。
* 状態の凡例: **有効** / **有効（近似）** / **撤回** / **置換→X**（別の規則に差し替え）/ **残置**（コード・タグは残るが適用なし）/ **改善版へ**。

## 11. 保留・未解決（2026-11-16 時点で今も有効なもの）

出どころ: 制作記録 §3、制作記録（11/16）、制作記録 末尾、各 notes。

1. **ガトリングビットが敵から離れすぎる**（ユーザー保留 11/09。DIR16RESET 後も NG）— 制作記録「残っているもの」、調査記録 34。
2. **サテライトレーザー（原作再現版）が即貫通**: 原作ではビーム ph0 のヒットフラグに bit0「ﾋｯﾄ中も高さ可変」が無く、当たっている間は高さが止まる（ph1 には有る）。DiveX に直接対応する値が見つからず、原作版は貫通のまま保留（ユーザー了承）。候補は (a) 自機側ヒットストップ Hit int16 をヒット間隔と同じにする、(b) ターン追加（改善版 SAT_HOLD と同じ）— 調査記録 60 §5。
3. **モーニングスター先端（TIPDETACH）**: 実機確認・ワークアラウンドの監修待ち（制作記録 11/15 夜）。
4. **空中 HG によるダメージ増加**: 原作は敵が空中にいる間 HG が溜まり、後半が ×1.6〜2.0。DiveX は被弾側の熱が打ち上げで増えないため再現不能（エンジン仕様差。ユーザー判断で保留 11/01）— 調査記録 24 §N1。
5. **引き算（原作）と掛け算（DiveX）の構造差**: 長いコンボの締め・最後の段は原作より小さい近似（HANDOFF §3 未解決 4）— 調査記録 18 §N、調査記録 24 §N1。
6. **slot 24 / 30（技中の歩き・サーチダッシュ補正率）**は甲テンプレのまま。技中に歩きベクトルがレバー入力で更新されるか（DiveX）と、BFE「移」（calc_speed +12）の意味が未解読 — 調査記録 40「次に詰めるなら」。
