# 05. BSDX .waz（技）と .mek 武装部のフィールド辞書

日付: 2026-10-22（クラウド内で完結。PC と BFE には依存しない）
対象: BALDR SKY DiveX の `.waz`（NeXAS_DX の JSON 表現）と `.mek` の WeaponInfo
成果物:
* `tools/waz_fields.json`: 機械可読の辞書。スロット 72 個、CEvent クラス 30 種、mek 武装フィールドを収録し、全 112 waz から集めた値域も入れてある。生成元は `tools/gen_waz_fields.py`
* `tools/waz_summary.py`: 機体の技・武装を表にする CLI（§9）

> 確度の表記: **【確認済】** は exe のコード・表、または全件のデータ照合で裏付けたもの。**【推定】** はプロパティ名の並び・初期値・統計から高い確度で推したもの。**【不明】** は仮説しかないもの。
> exe のアドレスはすべて VA（BaldrSky.exe、ImageBase 0x400000）で示す。

## 0. 要約

* waz の数値の大半は、**exe に残っているエディタ用プロパティ表**（`{型, 名前}` の配列）、**読み込み関数**、**初期化関数**の 3 つを突き合わせると名前が決まる。表の並び（＝メンバの並び）とファイル上の読み込み順は別物で、CEventHit ではファイル順が入れ替わっている。これを考慮しないと名前が一つずれる。
* **威力【確認済】**: `攻撃：メカ`（スロット 41）の CEventHit → サブオブジェクト[6]「攻撃力」→ Term（Term.grp グループ 21「攻撃」）の `paramList[0]`。typeList[0] が 0 なら直値、1 なら自分の HP の %、2 なら敵の HP の %。exe のダメージ計算関数 `0x63ba40` で式まで確かめた（§3.1）。
* **ヒット数・ヒット間隔・最低値・溜め反映率・各種コンボ補正・ヒットストップ・のけぞり（停止時間／ノックバック／ダウン時間／吹き飛び）** の名前とメンバ位置も特定した（§4.1、§4.2）。最低値と溜め反映率はダメージ計算コードで【確認済】、残りは【推定】（プロパティ順・初期値・統計が一致）。
* **モーション【確認済】**: CEventSprite の `actionGroupNumber` は spm のアニメ番号、`actionNumber` はそのアニメ内のパターン番号。104 機体の参照 23628 件がすべて範囲内に収まった。
* **SE【確認済】**: CEventSe の 16 バイトは `{SeGroup カテゴリ, 項目番号, 確率%, フラグ}`。7025 件中 7005 件が実在する SE 項目に解決した（残りは空き項目）。
* **ボイス【確認済】**: CEventVoice の 12 バイトは `{BatVoice キャラ番号, 台詞番号, 確率%}`。キャラ番号は mek の VoiceInfo の番号と一致する。
* **弾（飛び道具）【確認済】**: `エフェクト`（スロット 48）の CEventEffect → [3]「エフェクト番号」= WazaSelect（WazaGroup 番号、技番号）。**弾の威力は参照先の共通 waz（Tama01-05/Laser/Bomb）の技の Hit に入っている。** 共通 waz の技名は「ライフル：甲」「ライフル：レイン」のように使用者ごとに分かれているので、個別に調整できる。
* **値イベントの意味【確認済】**: CEventVal は `{開始値タイプ, 開始値, 終了値タイプ, 終了値}`。startFrame→endFrame の間で補間され、主値は int4。CEventValRandom は ±乱数幅付きの 6 値で、主値は int5（表示関数 `0x5f4660` と `0x5f4980` で確認）。
* **キャンセル・派生・ループの実体は「変更処理」（スロット 71、CEventChange）**。中身は「条件 Term 群 ⇒ 飛び先 Term」で、Term.grp の語彙を使って文章として表示できる（例: 「オブジェクト→接触→着地していたら ⇒ ターンジャンプ→１つ先」）。
* **熱**: 武装の基本の熱は mek の `蓄積熱量：初期値／最小値`【確認済】。waz の `熱量`（スロット 40）は、連射系などで技の途中に追加される熱である【推定】。
* 統計による検算: 甲の全武装で Lv1→Lv2→Lv3 の威力が 50→75→100 と規則的に増え、フレーム数は減る。FC 技は熱 80 で威力が大きい。スタンロッドは「停止時間 100」になっている。名前の割り当てに矛盾はない。

## 1. waz の構造（意味づけを含む）

```
waz = skillList[]                      // index = 技番号（mek の武装.wazSequence、WazaSelect.wazSequenceNo が指す）
skill = null(空き) | { skillNameJapanese, skillNameEnglish,
          phasesInfo[ターン] , skillSuffixList[] }
ターン(phase) = skillUnitCollection[] … 存在するスロットだけが {unitQuantity=スロット番号, skillInfoObjectList[], skillInfoUnknownList[]} として並ぶ
イベント = {startFrame, endFrame, …型固有…}   // ターン内のタイムライン
```
* NeXAS_DX の「phase」は、エンジンでは **「ターン」** と呼ばれる【確認済: Term.grp の TURN グループと「ターンジャンプ」】。1 つの技は複数のターンを持ち、変更処理のジャンプで次のターン（「１つ先」）、指定ターン、技の終了へ移る。ループもターンジャンプで作る。
* イベントは startFrame〜endFrame の間だけ有効になる。モーションはフレーム区間ごとに切り替わる（例: ボディブロー Lv1 = 0-3, 4-8, 9-11, 12-28, 29-34）。
* `skillSuffixList` は (ターン番号, 0) の並びで、エディタのツリー表示用と見られる（例外 36 件は (1,3) のような枝分かれ）【推定、編集対象外】。
* `skillInfoUnknownList`（id 0xFF）はスロットごとの付属リスト `{start, end, int1, int2, int3}` で、99% が (-1, 1, -2)。ループ範囲かブロック指定と見られる【不明、編集対象外】。

### 1.1 値イベント（CEventVal / CEventValRandom）【確認済】
| JSON | CEventVal | CEventValRandom |
|---|---|---|
| int1 | 開始値タイプ 0=直値、1=前の値±（相対） | 開始値タイプ |
| int2 | 開始値 | 開始値 |
| int3 | 終了値タイプ 0=直値、1=前±、2=開始値± | 開始値の乱数幅 ± |
| int4 | **終了値（主値）** | 終了値タイプ |
| int5 | — | **終了値（主値）** |
| int6 | — | 終了値の乱数幅 ± |

根拠: 表示関数 `0x5f4660` の書式文字列 `"%4d"`、`"前%c%4d"`、`"%s ⇒ "`、`"%s開始値%c%4d"` と、`0x5f4980` の `"%s(±%4d)"`。開始値はイベント長が 2 フレーム以上のときにだけ使われる（そのときだけ表示される）。

### 1.2 Term（条件・指定子）【一部確認済】
CEventTerm（型 5,6,9,10,11,0x20）、CEventChange、CEventMove などに入っている `bsdxInfoCollection` は、**Term.grp（30 グループ）の語彙で書かれた式**である。
* `int1` = グループ番号【確認済】。CEvent の型ごとに固定で、exe の factory `0x5db500` が ctor `0x641ad0` に渡す値と一致する: 位置=20 POS、無効条件=4 CHANGE、方向=18 ANGLE、速度タイプ等=23 PARAM、**攻撃力=21 ATTACK2**。変更処理の条件は 0 PARENT、飛び先は 16 JUMP。
* `typeList` = 項目番号の列【推定・高確度】。先頭がグループ int1 の項目で、その項目の param2 が 0 以上なら次の値はそのサブグループの項目を指す。例 `[2,7,16]` = 親:オブジェクト → オブジェクト(単体):接触 → 接触:着地していたら。
* `paramList` = 項目文字列の `$v1`、`$v2` に入る数値【確認済: `0x63bf50` が paramList[i] を返し、ダメージ計算が使う】。
* `intList3` / `intList4` = 対象オブジェクトの選択値と見られる【不明】。`int2` は不明。

### 3.1 ダメージ計算（`0x63ba40`）【確認済】
```
p = 攻撃力Term.paramList[0]
base = p                      (typeList[0]==0: 直値)
     = 自HP × p / 100          (==1)
     = 敵HP × p / 100          (==2)
条件付きで base × 150/100      (攻撃側オブジェクトの [+0x18a4] が真のとき。FC/特殊状態か?【不明】)
d = base × 引数% / 100        (呼び出し側が渡す補正率。コンボ補正と見られる)
d = max(d, 攻撃力最低値[+0x20])
if 溜め反映率[+0x24] >= 0:  d = d × (溜め量% + 溜め反映率) / 100
```

## 7. 統計による検算
* 甲（武装 153）: Lv1/2/3 の威力は 50/75/100 が基本で、フレーム数は Lv が上がると短くなる（例 ボディブロー 35→31→29F）。パイルバンカー 150、クラッシュハンマー 250、アルティメットナックル 50×4+衝撃波 10×2 と、感覚に合う。
* 空（Sora）: FC 技（攻撃Lv 3、熱 80）はクリティカルアロー 300+100+12、エクストリームサイクロン 100×2+多段。通常技は 40〜100。
* スタンロッドは「停止時間 100、ﾋｯﾄﾊﾞｯｸ 5、ダウン時間 1」で、行動不能の長い技になっている。これが停止時間の解釈の傍証になる。
* ドリルやチェーンソーのような持続型は「ヒット数 -1、間隔 3〜5」になっている。
* ザコ（メッサー）: ワンツー 50×2、ミサイル 37。弾は Tama02「高速直進バズーカ」で、他のザコと共有している。

## 8. 残っている不明点（優先度順）
1. **ヒット数／ヒット間隔／ヒットストップ／のけぞり各値の実機確認**: 名前はプロパティ順からの推定で、ずれている可能性は低い。それでも 1 技だけ値を極端にして（例: ボディブロー Lv1 の威力 50→500、ヒット数 1→5、停止時間 1→120）実機で確かめるのが確実（Phase 0 の Update3.pac と同じ方式）。
2. ターンの長さの決まり方（最後のイベントの endFrame か、変更処理の発生か）。変更処理の条件が複数あるときの AND/OR。
3. Hit の無名メンバ 2 個（+0x14 の 0-3、+0x64 の 0-2）、フラグのビット、鉄ヒットＳＥ、キャンセルフラグ（+0x60）の値の意味。
4. Effect のスカラ int4〜int11 の対応。Term の intList3/intList4。
5. ダメージの ×1.5 条件（攻撃側の `+0x18a4`）と、呼び出し側が渡す補正率の出どころ（コンボ補正の累積式）。
6. waz の「熱量」の単位（mek の熱は 1 本 = 80 と言われているが、waz 側の値は 50-2000）。
7. Status（パラメータ変動）のバイト列。SpriteYure/ScreenYure/Blur/SpriteAttr のパラメータ。

## 10. GUI エディタの構成案（この調査結果を前提にしたもの）
* **データ層**: NeXAS_DX（Java）の parse/generate をそのまま使う。waz/mek の JSON を読み書きし、バイナリの往復は 112/112 で一致済み。GUI は JSON を編集し、保存時に generator → 再パースして一致を確認 → Update3.pac に入れる（tools/nexaspac.py）。
* **スキーマ駆動**: 画面は `waz_fields.json` から自動で作る（スロット名、フィールド名、型、確度、editable、値域）。確度が 不明 の項目は「詳細」タブに生の値だけ出して、誤操作を防ぐ。
* **画面構成（案）**
  1. 機体の選択 → 武装一覧（mek の武装 + 技の要約。`waz_summary` と同じロジック）
  2. 技エディタ: **ターン×スロットのタイムライン**（横軸がフレーム。イベントは帯で、ドラッグで start/end を変える）。モーション帯に spm のアニメ名を出す（プレビューは NeXAS_SPM_VIEWER を流用できる）
  3. **攻撃パネル**（Hit）: 威力、ヒット数、間隔、最低値、補正 4 種、ヒットストップ、のけぞり 4 タブ（処理タイプが「同じ」の欄は灰色にする）
  4. **弾パネル**: Effect → 参照先の共通 waz の技へ移動するリンク。共通の技を変えると他の機体にも効く場合があるので警告を出す（参照元の一覧を表示する）
  5. SE/ボイスはドロップダウンで選ぶ（SeGroup/BatVoice の名前）。変更処理は Term.grp の語彙を使った条件ビルダーにする
  6. 熱・攻撃Lv・カテゴリは mek 武装の表で編集する
* **移植パイプラインとのつながり**: BHE→BSDX 変換（JsonTransWaz）の出力も同じ JSON なので、そのまま GUI で手直しできる。TOORU（BFE）を移植する場合も、BSDX の waz JSON にさえ落とせば同じ GUI が使える。
* 実装: Java 側の資産（NeXAS_DX、SPM_VIEWER は JavaFX）に合わせて **JavaFX** にするのが自然。ただし Windows の JavaFX ランタイムが必要になる。軽く済ませるなら Python + Web UI（JSON の編集だけを行い、生成は Java CLI を呼ぶ）でもよい。
